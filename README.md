## 开一个 CS2 服到底吃多少资源

官方镜像文档给的最低配置是 2 CPU、2GiB 内存、60GB 磁盘，并注明"装 mod 可能需要更多空间"。60GB 这个数字在文档里被单独强调过一次，因为 CS2 服务端本体加更新残留很容易把这盘吃满，工坊地图和 CSTV 录像还会继续往上堆。

最低配置不等于舒适配置。第三方服务器目录里能看到的真实负载分几个档：死斗服常见 23/32 或 32/32，Surf 服 41/64，僵尸逃跑 63/64、64/64 满员是常态，还有标题直接标着 128 Tick 的社区服。10 人竞技服和 64 人僵尸逃跑服完全不是同一种负载，后者的插件、实体数量、语音转发、CSTV 转播全都在抢 CPU 和上行带宽。

按人数和玩法给档位判断：

- **10 人以内竞技、练枪、朋友内战**：2 核 2G 够用，官方最低门槛就是照这个规模定的。
- **20–30 人社区服，带常规插件**：4 核 4G，内存留出插件和 SourceMod 的余量。
- **40 人以上，或僵尸逃跑、Surf 这类满员 64 人的模式**：4 核 8G 起步，上行带宽尽量选 60M 以上。
- **要开 CSTV 转播、自动录 demo、挂多个实例**：再往上加，别在内存上省。

带宽比 CPU 更容易被忽略。洛杉矶 2 核 2G 的上行是 30M，1 核 1G 只有 20M，香港标配版上下行各 20M。人一多，上行先到顶。CSTV 尤其吃带宽，`TV_MAXRATE` 默认 0 表示不限制，开转播前建议设个上限，`TV_RELAYVOICE=1` 还会把语音一起转给观众。

## 从零到能进服：可以照着敲的步骤

官方 Docker 镜像 `joedwards32/cs2` 里装的就是 CS2 专用服务器，镜像仓库另有 GitHub 上的 `ghcr.io/joedwards32/cs2` 同一份，启动时自动更新游戏。整套流程如下。

**1. 先申请服务器令牌。** 这是开服的前置门槛，没有它服务器起不来。令牌在 Steam 的服务器令牌申请页生成，对应镜像是 `SRCDS_TOKEN` 这个环境变量。很多新手卡在这一步，以为买了机器就能开。

**2. 装好 Docker，拉镜像。**

**3. 建持久化目录并改属主。** 容器里的服务端以 uid 1000 的非特权用户（名字叫 steam）运行，目录权限不对会写不进去：

bash
mkdir -p $(pwd)/cs2-data
chown 1000:1000 $(pwd)/cs2-data


**4. 一条命令起服，把 27015 的 TCP 和 UDP 一起映射，CSTV 的 27020 UDP 也放通：**

bash
SRCDS_TOKEN="..." \
docker run -d --name=cs2 \
  -e SRCDS_TOKEN="$SRCDS_TOKEN" \
  -v $(pwd)/cs2-data:/home/steam/cs2-dedicated/ \
  -p 27015:27015/tcp -p 27015:27015/udp -p 27020:27020/udp \
  joedwards32/cs2


注意 `CS2_PORT=27015` 在文档里的注释是 "listen port tcp_udp"，同一个端口两种协议。云服务器安全组或防火墙只放 UDP 或者只放 TCP，服务器列表里能刷出来但玩家连不进去。

**5. 改名、设密码、改人数上限。** `CS2_SERVERNAME` 是显示名，`CS2_PW` 是进服密码，`CS2_RCONPW` 是远程管理密码，`CS2_MAXPLAYERS` 默认只有 10，开社区服必须改。

**6. 选游戏模式。** 用 `CS2_GAMEALIAS` 填 casual、competitive、deathmatch 这类别名最省事；也可以走 `CS2_GAMETYPE` 加 `CS2_GAMEMODE` 的组合，这两个只在没定义别名时生效。起始图 `CS2_STARTMAP` 默认是 de_inferno，地图池 `CS2_MAPGROUP` 默认 mg_active。

**7. 换工坊图。** 设 `CS2_HOST_WORKSHOP_MAP` 或 `CS2_HOST_WORKSHOP_COLLECTION`，进服后用 rcon 执行 `ds_workshop_listmaps` 查看、`ds_workshop_changelevel 地图名` 换图。注意设了工坊地图后，`CS2_MAPGROUP` 和 `CS2_STARTMAP` 会被忽略。

**8. 让别人进来。** 对外只需要 IP 加端口可达，第三方服务器目录的"连接"按钮干的就是把 IP 和端口交给 Steam 客户端。你自己在控制台 `connect IP:27015` 一样。

**9. 游戏更新后怎么办。** 重启容器就行，镜像启动时会自动更新服务端。

想一次写清楚配置的，用 compose 也行，`docker compose --file examples/docker-compose.yml up -d cs2-server`，起来之前先把密码和令牌改掉。

## 四个教程里很少提的坑

**空服休眠会崩。** `CS2_SERVER_HIBERNATE=1` 是让服务器没人的时候进入低 CPU 状态，文档的注释原话是"hibernation has been observed to trigger server crashes"，观察到的现象是会触发服务器崩溃，默认就是关闭。为了省空服那点 CPU 把它打开，换来的是不定时崩服，不值。

**环境变量里的斜杠要转义。** 服务器名想写 "My Server 1/3"，环境变量里必须写成 `My Server 1\/3`，否则配置解析阶段会出现预期外的行为。这件事文档专门用加粗提醒过，但很多人是改完名字发现显示不对才回头找原因。

**用了 `CS2_RCON_PORT` 就要多映射一条 TCP。** 这个参数是通过一个简单的 TCP 代理让 RCON 监听在别的端口，方便不支持混合协议端口的平台。设了它，`docker run` 里得再加一条 `-p 新端口:新端口/tcp`，漏了就连不上。

**服务端文件被改坏了，用 `STEAMAPPVALIDATE=1` 重校验。** 默认是 0 跳过校验，改了参数重启容器会重新校验并补下缺失文件。另外 `CS2_SERVER_DELTATICKS_ENFORCE=2` 的默认值会踢掉没有按序确认 delta ticks 的客户端，遇到玩家莫名被踢可以先看这个。

要装 MetaMod 或 SourceMod，镜像留了两个钩子脚本：`/home/steam/cs2-dedicated/pre.sh` 在服务端启动前执行，`post.sh` 在停止后执行，持久化目录挂出来之后可以直接编辑，文档里点名的用途就是 enabling metamod。模式默认配置放在 `game/csgo/cfg/` 下，比如 `gamemode_competitive.cfg`，想覆盖默认值就同目录建一个 `gamemode_competitive_server.cfg`，升级不会把你的改动冲掉。

CS2 状态页的数据中心列表里，中国有北京、上海浦东、广东、成都，亚洲还有香港、日本、韩国、新加坡，欧美一堆节点。第三方服务器目录按国家分页，中国的僵尸逃跑服常见 64/64 满员，美国、德国、土耳其各自有一批固定玩家。玩家对"机房离自己近"的敏感度是真实的，这份分布就是选地域的依据。

判断规则很简单：

- 玩家集中在华东、华南，选香港节点或温州、宁波、宿迁、镇江这些华东机房。香港的优势是免备案、面向大陆的访问质量好，代价是同配置比美国贵。

- 玩家分散在国内外，优先保国内主力玩家，海外玩家在高延迟下也能玩，反过来不行。

## 什么情况下不用买云服务器

五个人以内、一周玩两次，买月付服务器是浪费。CS2 自带本地开房，或者去现成的社区服找个空位，成本为零，还不用管令牌、更新、端口。真正值得自己开的场景有这么几个：需要一个固定 IP 让固定的一批人长期进；要装插件、改规则、办比赛；要做社区运营、要有人气积累；要开 64 人满员的 ZE 或 Surf 服。这些需求现成服务器满足不了，钱才花得值。

还有一类人容易买错：只在周末开两天服，却买了月付套餐。这种节奏可以先看游戏云的动态计费，基础月租压得低，CPU 用得多的日子多付一点。真按小时算的是云应用那条产品线，不适合自己装 Docker 跑 CS2，别选错。

## 常见问题

**10 个人玩，2 核 2G 够吗？**
够。官方最低要求就是 2 CPU / 2GiB，10 人竞技服的负载在这个范围内。内存别贴着 2GiB 卡死，装插件就得往上加。

**为什么我买了 30GB 硬盘的套餐，服务端起不来？**
官方文档要求至少 60GB 空闲磁盘，服务端本体加更新残留就要这么多，装 mod 还要更多。30GB 的套餐必须扩容，扩容费按 0.3–0.4 元/GB/月算。

**能装 SourceMod 和 MetaMod 吗？**
能。镜像留了 `pre.sh` 启动前脚本，文档明确写了这个钩子可用于 enabling metamod。装之前把磁盘留足。

**换机器了，数据怎么迁？**
服务端所有东西都在持久化目录 `/home/steam/cs2-dedicated/` 里，整目录打包搬到新机器同一个挂载点，令牌和启动参数照抄，起来就能用。

**游戏更新后要手动做什么？**
重启容器。镜像启动时会自动更新服务端，不需要手动跑更新命令。
